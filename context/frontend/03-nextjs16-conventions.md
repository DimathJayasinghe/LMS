# 03 — Next.js 16 Conventions

> The app runs **Next.js 16.2.6**. Several App Router APIs differ from what older tutorials (and model
> training data) show. The frontend's `AGENTS.md` warns about exactly this. This doc is the cheat-sheet;
> the **authoritative** source is the bundled docs at `frontend/node_modules/next/dist/docs/01-app/`.
> When in doubt, open them.

---

## 1. The traps that bite (read before coding)

| Feature | The old way (wrong now) | Next.js 16 (correct) |
|---|---|---|
| `params` in pages/layouts | `params.id` (sync object) | **`params` is a `Promise`** → `const { id } = await params` |
| `searchParams` in pages | `searchParams.q` (sync) | **`Promise`** → `const { q } = await searchParams` |
| Route prop types | hand-written interfaces | Global **`PageProps<'/route'>`** / **`LayoutProps<'/route'>'`** helpers (generated) |
| `fetch` caching | cached by default | **Not cached by default**; opt in with `use cache`, or stream with `<Suspense>` |
| Dynamic APIs | `cookies()`/`headers()` sync | async — `await cookies()`, `await headers()` |
| Navigation | `<a href>` | **`<Link href>`** from `next/link` for client-side nav + prefetch |
| Client hooks | free to use anywhere | only in `"use client"` files; `useSearchParams`/`useRouter` from `next/navigation` |

If a snippet you're about to write treats `params`/`searchParams` as a plain object, stop — it must be `await`ed.

## 2. Routing model

File-system routing under `app/`:

- **Folder** = URL segment. **`page.tsx`** = the route's UI. **`layout.tsx`** = shared shell wrapping children.
- **`[id]`** = dynamic segment; **`[...slug]`** = catch-all; **`(group)`** = route group (no URL segment,
  used to give a set of routes a shared layout — we use `(marketing)` and `(app)`).
- Special files: `loading.tsx` (Suspense fallback for the segment), `error.tsx` (error boundary, must be a
  client component), `not-found.tsx`, `route.ts` (API/route handler — we rarely need these; the backend owns the API).

### Page with a dynamic param

```tsx
// app/(app)/classes/[id]/page.tsx
export default async function ClassPage({ params }: PageProps<'/classes/[id]'>) {
  const { id } = await params            // params is a Promise
  const course = await api.get(`/classes/${id}`)  // fetch on the server
  return <ClassDetails course={course} />
}
```

`PageProps` / `LayoutProps` are **global** (generated by `next dev` / `next build` / `next typegen`) — no import.
`params` for static routes resolves to `{}`.

### searchParams (server) vs useSearchParams (client)

- Need the query to **load data**? Use the `searchParams` prop (server) — `const { page } = await searchParams`.
  Reading it opts the page into dynamic rendering.
- Query only affects **already-loaded client UI** (filtering a client list)? Use `useSearchParams()` from
  `next/navigation` in a `"use client"` component.

## 3. Layouts

- The **root layout** (`app/layout.tsx`) is required and must render `<html>` and `<body>`. Ours loads Poppins
  and (going forward) mounts global providers around `{children}`.
- Nested `layout.tsx` files wrap their subtree and **preserve state across navigation** (they don't re-render on
  child navigations). Use `(app)/layout.tsx` for the authenticated shell (sidebar/topbar + auth guard).
- Render providers **as deep as possible** — wrap `{children}`, not `<html>` — so static server content stays optimizable.

---

## 4. Data fetching

Fetch **on the server** in Server Components by default (async component, `await`). Benefits: no client JS,
secrets stay server-side, faster first paint.

```tsx
export default async function Page() {
  const data = await api.get('/subjects')   // runs on the server
  return <SubjectList subjects={data} />
}
```

Key facts:
- Identical `fetch` calls in one render are **memoized** — fetch in the component that needs the data; no prop drilling.
- `fetch` is **not cached** by default and blocks render until it resolves. For slow data, wrap the component in
  `<Suspense fallback={<Skeleton/>}>` (or add a `loading.tsx`) to stream.
- To cache intentionally, use the `use cache` directive (see bundled docs `directives/use-cache`). Most LMS data
  is per-user and auth-gated, so we mostly **don't** cache — we stream.
- **Client-side fetching** (when you truly need it — live-updating widgets, camera/QR flows): use React's `use()`
  with a promise passed from the server, or a tiny `fetch` in an effect. We deliberately avoid adding SWR/React
  Query unless a case demands it.

### Our data flow (with cookie auth)

Because auth is via **HTTP-only cookies**, server-side fetches must forward the incoming request's cookies to the
backend, and browser fetches must send `credentials: 'include'`. The `api` client (Doc 04) handles both modes —
**always go through it**, never raw `fetch` to the backend.

## 5. Loading, error & empty states

- `loading.tsx` in a segment → instant fallback while the server renders (wraps the page in `<Suspense>`).
  Make it a **meaningful skeleton**, not "Loading…".
- `error.tsx` → a `"use client"` error boundary for the segment with a `reset()` action.
- `not-found.tsx` → 404 UI; call `notFound()` from `next/navigation` to trigger it.
- Empty state (query succeeded, zero rows) is **app logic**, not a Next file — render an `EmptyState` component
  (Doc 05 §4). Don't confuse "empty" with "loading".

---

## 6. Navigation

- Use `<Link href="/classes">` (from `next/link`) for all internal navigation — it prefetches and does
  client-side transitions. Replace the landing page's `<a href="/…">` internal links with `<Link>`.
- Programmatic navigation in client components: `const router = useRouter()` from **`next/navigation`**
  (not `next/router`), then `router.push('/dashboard')`.
- External links stay `<a>` with `rel="noopener noreferrer"` when `target="_blank"`.

---

## 7. Fonts

- Load fonts with `next/font` (already done: Poppins in `app/layout.tsx`, exposed as `--font-poppins`).
  `next/font` self-hosts and avoids layout shift — **do not** add `<link>` tags to Google Fonts.
- To use a second font (e.g. a monospace for exam timers), load it via `next/font` and map it to `--font-mono`.

---

## 8. Images

- Use `next/image` (`import Image from 'next/image'`). Provide `width`/`height` (or `fill` + a sized, positioned
  parent) and a meaningful `alt`. This is already the pattern in `CourseCard`.
- Remote images (e.g. Bunny thumbnails, avatar hosts) need their host allow-listed in `next.config.ts`
  (`images.remotePatterns`). Add hosts there when you introduce them.

---

## 9. Metadata

- Export a `metadata` object (or `generateMetadata` for dynamic routes) from a `page`/`layout` — don't write
  `<head>` tags manually.
  ```tsx
  export const metadata = { title: 'Classes · LMS', description: '…' }
  ```
- The root layout already sets a default `title`/`description`; per-route metadata overrides it.

---

## 10. Before you commit

- Run **`npm run build`** — it's the real check for `params` misuse, server/client boundary errors, and type
  problems that `dev` may tolerate.
- If you used a Next feature you're not 100% sure about, open the matching file under
  `node_modules/next/dist/docs/01-app/` and confirm. That directory is the version-accurate reference — your
  memory of Next.js may be a version or two behind.
