# Organization settings

All routes require authentication and `SUPER_ADMIN`. Organization is resolved from the authenticated user. `GET /api/settings` returns `{ status: "success", data: [{ key, value, default }], count }`. Missing rows use registry defaults.

`PATCH /api/settings/:key` accepts `{ "value": ... }` and returns `{ status: "success", data: { key, value } }`. Unknown keys and values outside their registered type or range return 400; other roles receive 403. A changed value and `SETTING_CHANGED` audit row are committed together. Changes affect future decisions. `exams.marking.markerMayOverrideTeacher` remains fixed at false.

Account-change settings: `identity.roleChange.reasonRequired` (default true) requires a reason on a role change; `identity.staffDeactivate.requireHandover` (default true) refuses to deactivate a teacher whose classes are not handed over, and turning it off lets the account leave its classes behind (they then show as classes without a teacher); `identity.handoverLookaheadDays` (1–60, default 14) is how far ahead a session counts as pending when the classes of a leaving teacher are listed; `handover.defaultEffectiveMonth` (`NEXT` or `CURRENT`, default `NEXT`) is recorded in the audit row of a hand-over as the month the new teacher's income share starts, until the income share exists. The step-up password for role changes and staff deactivations follows `identity.stepUp.required` and `identity.stepUp.actions`.

`fees.graceDays` defaults to 10 (0–31); `fees.graceRequiresPreviousMonthPaid` defaults to true. A student with an active enrollment is covered by a successful payment for the organization billing month, or during grace by the previous month's successful payment. If the previous-payment requirement is switched off, grace applies to any active enrollment. A current-month payment that was refunded never receives grace. Payments on any enrollment of the course count, even after that enrollment was cancelled. Setting grace to 0 restores the strict monthly gate. Other registry defaults and ranges are defined in `backend/src/config/settings-registry.ts`.
